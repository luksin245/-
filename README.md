# 사업용 통장 거래내역 관리 프로그램

법인 사업용 통장 1개의 입출금 내역을 관리하는 개인/사내용(로컬) 프로그램입니다.
인터넷에 공개되지 않고 내 컴퓨터에서만 실행되며, 데이터도 내 컴퓨터 안에만 저장됩니다.

전체 기술 설계는 [DESIGN.md](DESIGN.md)를 참고하세요. 이 문서는 **사용법 전체**를 다룹니다.

> ⚠️ **이 프로그램은 회계·세무 신고 프로그램이 아닙니다.** 복식부기 분개, 법인세 신고,
> 부가가치세 신고를 대신 처리해주지 않습니다. 어디까지나 통장 거래내역을 정리하고
> 세무사에게 전달할 자료를 준비하는 것을 돕는 개인용 관리 도구입니다. 회계 처리가
> 불확실한 거래는 항상 '미분류'나 '확인필요' 상태로 남겨두고, 최종 판단은 세무사 등
> 전문가와 상의하세요.

## 1. 프로그램 소개

- 법인 명의로 개설한 **사업용 통장 1개**의 입출금 내역을 정리하고 관리하기 위한 프로그램입니다.
  (통장이 여러 개인 경우를 위한 다계좌 관리 기능은 없습니다.)
- 거래를 직접 입력하거나, 통장 거래내역 이미지/PDF를 업로드해 OCR(광학 문자 인식)로
  자동 추출한 뒤 검토해서 등록할 수 있습니다.
- 대시보드로 수입/지출/매출/비용 현황을 확인하고, CSV/Excel로 내보내 세무사에게 전달할
  수 있습니다.
- Streamlit이라는 파이썬 웹 프레임워크로 만들어졌으며, 웹 브라우저 화면으로 보이지만
  **내 컴�터 안에서만 동작**하고 외부 인터넷에 공개되지 않습니다.

## 2. 최초 설치

### 2-1. Python 설치

Python 3.11 이상이 필요합니다. [python.org](https://www.python.org/downloads/)에서
설치 파일을 내려받아 설치하세요. 설치 화면에서 **"Add python.exe to PATH"** 옵션을
반드시 체크해야 합니다.

### 2-2. 필요한 패키지 설치

프로젝트 폴더에서 명령 프롬프트(cmd)를 열고 아래 명령을 실행합니다.

```
pip install -r requirements.txt
```

### 2-3. (선택) OCR을 사용하려면: Tesseract OCR 설치

"통장 가져오기(이미지/PDF 업로드로 거래 자동 인식)" 기능을 쓰려면 Tesseract OCR
프로그램을 **별도로** 설치해야 합니다. (수동 입력만 쓸 계획이라면 이 단계는 건너뛰어도
됩니다 - 나머지 모든 기능은 정상 동작합니다.)

1. [Tesseract OCR Windows 설치 파일](https://github.com/UB-Mannheim/tesseract/wiki)을 내려받아 설치합니다.
2. 설치 중 **"Additional language data" → Korean(한국어)** 체크박스를 반드시 선택하세요
   (기본값은 영어만 포함되어 있어, 한국어 인식을 위해 별도로 체크해야 합니다).
3. 설치 후 Tesseract 실행 파일이 시스템 PATH에 등록되어 있는지 확인하세요. 설치
   프로그램이 자동으로 등록해주지 않는 경우, 설치 폴더(예:
   `C:\Program Files\Tesseract-OCR`)를 직접 환경변수 PATH에 추가해야 합니다.
4. Tesseract가 설치되어 있지 않은 상태로 "통장 가져오기"를 시도하면, 화면에
   "Tesseract OCR 실행 파일을 찾을 수 없습니다" 라는 안내 메시지가 표시됩니다 (프로그램이
   멈추거나 잘못된 결과를 만들지 않습니다).

## 3. 평소 실행 방법

- **`run.bat` 파일을 더블클릭**하면 Python/패키지 설치 여부를 확인한 뒤 자동으로
  실행되고 브라우저가 열립니다.
- 또는 명령 프롬프트에서 직접 실행할 수도 있습니다.
  ```
  streamlit run app.py
  ```
- 자동으로 브라우저가 열리지 않으면 `http://localhost:8501` 주소로 직접 접속하세요.

## 4. 프로그램 종료 방법

- `run.bat`을 실행해 열린 검은색 명령 프롬프트 창을 그냥 닫으면 프로그램이 종료됩니다.
- 명령 프롬프트에서 직접 실행했다면, 그 창에서 `Ctrl + C`를 누른 뒤 창을 닫으면 됩니다.
- 브라우저 탭만 닫는 것으로는 프로그램(서버)이 종료되지 않으니, 실행에 사용한
  검은 창을 닫아야 완전히 종료됩니다.

## 5. 화면(메뉴) 구성

왼쪽 메뉴에 다음 6개 화면이 있습니다.

| 메뉴 | 용도 |
|---|---|
| 🏠 대시보드 | 수입/지출/매출/비용 현황을 한눈에 확인 |
| 📋 거래내역 | 저장된 거래 조회·검색·필터·수정·삭제, 내보내기 |
| 📝 거래등록 | 거래를 하나씩 직접 입력 |
| 🏦 통장 가져오기 | 통장 거래내역 이미지/PDF 업로드 → OCR 인식 → 검토 후 저장 |
| 🗂️ 기준정보 관리 | 거래처 / 카테고리 / 업무유형 / 계정과목 / 자동분류 규칙 관리 |
| ⚙️ 설정 | DB 정보 확인, 백업 생성/복구 |

## 6. 거래등록 (수동 입력)

1. **거래일자**, **수입/지출**, **거래내용**, **금액**은 필수 입력 항목입니다.
2. 금액은 `500,000`처럼 쉼표를 넣어도, 숫자만 입력해도 됩니다. 0원 이하는 저장되지 않습니다.
3. **거래처**를 선택하면, 그 거래처에 등록된 기본 카테고리/업무유형이 자동으로
   채워집니다(추천값일 뿐이며 자유롭게 바꿀 수 있습니다).
4. **회계구분**과 **계정과목**은 [10장](#10-회계구분이란-무엇인가요)과 [15장](#15-기준정보-관리---계정과목)을
   참고하세요. 확실하지 않으면 회계구분은 '미분류'로 그대로 두어도 됩니다.
5. 저장하면 "거래내역이 저장되었습니다." 메시지와 함께 입력폼이 비워져 바로 다음
   거래를 이어서 입력할 수 있습니다.
6. 같은 내용을 실수로 연속 클릭해도, 5초 이내의 완전히 동일한 내용은 중복 저장을
   막고 경고 메시지만 표시합니다.

## 7. 거래내역 조회 / 검색 / 필터

- **검색 / 필터** 영역에서 시작일·종료일·수입/지출·카테고리·거래처·업무유형·회계구분·증빙
  여부를 원하는 대로 조합해서 좁혀볼 수 있습니다(여러 조건 동시 적용 가능).
- **거래내용 검색**에 "KT"처럼 일부 단어만 입력해도 포함된 거래를 모두 찾아줍니다.
- 조건을 처음 상태로 되돌리려면 **필터 초기화** 버튼을 누르세요.
- 표 위쪽 **검색 결과 요약**에 현재 필터 기준 조회 건수·총수입·총지출·순금액이 표시됩니다.
- 조건에 맞는 거래가 없으면 "조건에 해당하는 거래내역이 없습니다."라고 안내합니다.
- 필터에는 비활성화된 거래처/카테고리/업무유형도 "(비활성)" 표시와 함께 계속 나타납니다 -
  과거에 쓰던(지금은 비활성인) 항목으로도 검색할 수 있어야 하기 때문입니다.

## 8. 거래 수정 / 삭제

### 수정

1. 거래 목록 아래의 **수정 또는 삭제할 거래 선택** 드롭다운에서 원하는 거래를 고릅니다.
2. **✏️ 선택한 거래 수정** 버튼을 누르면 기존 값이 미리 채워진 수정 창이 열립니다.
3. 필요한 항목을 고쳐서 **저장**을 누르면 반영됩니다.
4. **수입 ↔ 지출을 변경하면 카테고리 선택이 자동으로 비워집니다.** 새 유형에 맞는
   카테고리를 다시 선택해주세요.

### 삭제 (한 건)

1. 위와 동일하게 드롭다운에서 거래를 선택합니다.
2. **🗑️ 선택한 거래 삭제** 버튼을 누르면 확인 창이 뜹니다.
3. 내용을 확인한 뒤 **삭제**를 눌러야 실제로 지워지며, **취소**를 누르면 아무 변화 없이
   창만 닫힙니다. 삭제된 거래는 되돌릴 수 없으니 신중하게 확인하세요.

### 여러 건 한꺼번에 삭제

1. 거래 목록 표의 맨 왼쪽 **선택** 칸을 체크해서 지울 거래를 고릅니다.
   - 검색/필터로 좁혀둔 결과를 통째로 지우려면 표 위의 **현재 검색 결과 전체 선택**을
     체크하세요 (예: 기간을 9월로 좁힌 뒤 전체 선택 → 9월 거래만 선택됨).
   - 전체 선택 후 표에서 일부만 체크를 풀 수도 있습니다.
2. 표 아래 **🗑️ 선택한 N건 삭제** 버튼을 누르면 선택한 건수, 기간, 수입/지출 합계를
   보여주는 확인 창이 뜹니다.
3. **삭제**를 누르면 지우기 직전에 현재 데이터 전체가 `pre_bulk_delete_날짜.db` 이름으로
   **자동 백업**된 뒤 삭제됩니다. 잘못 지웠다면 설정 → 백업 목록 / 복구에서 그 백업을
   선택해 삭제 전 상태로 되돌릴 수 있습니다.
4. 검색 조건을 바꾸면(목록이 달라지면) 체크했던 선택은 자동으로 모두 풀립니다 — 다른
   거래가 실수로 선택된 채로 남아 잘못 지워지는 일을 막기 위해서입니다.

## 9. 대시보드

### 조회 기간

- **빠른 선택**: 이번 달 / 지난달 / 최근 3개월 / 올해 / 직접 선택 중 고를 수 있습니다.

### KPI 카드와 직전 기간 비교

- 상단에 **총수입 / 총지출 / 순현금흐름 / 거래건수**를 표시하고, 각 카드 아래에 직전
  같은 길이 기간과 비교한 증감을 보여줍니다.
- 아래 보조 지표로 수입/지출 거래 건수와 평균 거래금액을 표시합니다.

### 회계구분 기준 요약 (총매출 / 총비용)

- 통장 기준 총수입/총지출과는 **별개로**, 거래마다 지정한 회계구분을 기준으로 집계한
  **총매출**과 **총비용**을 함께 보여줍니다.
- 화면에 "⚠️ 위 총수입/총지출은 통장 입금·출금 기준이고, 아래 총매출/총비용은
  회계구분 기준입니다"라는 안내 문구가 항상 표시됩니다. **총수입=총매출이 아닙니다.**
  자세한 설명은 [10장](#10-회계구분이란-무엇인가요)을 참고하세요.

### 차트

1. **월별 수입·지출 추이**
2. **지출 카테고리별 금액** (금액이 큰 순, 비중 %)
3. **업무유형별 매출**
4. **거래처별 매출 TOP 10**

카테고리/업무유형/거래처가 지정되지 않은 거래는 '미분류'로 합산되어 함께 표시됩니다
(제외되지 않습니다).

### 최근 거래내역

대시보드 맨 아래에 선택 기간 기준 최근 거래 10건을 보여줍니다.

## 10. 회계구분이란 무엇인가요

**"수입/지출"은 통장에 돈이 들어왔는지 나갔는지(입금/출금)만 나타냅니다.** 그 돈이
실제로 회사의 매출인지, 비용인지, 단순 자금이동인지는 **다른 개념**이며, 이를 위해
거래마다 **회계구분**을 별도로 지정합니다.

| 회계구분 | 의미 | 예시 |
|---|---|---|
| 매출 | 실제 영업활동으로 벌어들인 수익 | 고객사 자문료 입금 |
| 비용 | 실제 영업활동에 사용한 지출 | 사무실 임차료 출금 |
| 자금이동 | 회사 내부적인 단순 자금 이동 (매출/비용 아님) | 다른 계좌로의 단순 이체 |
| 비매출입금 | 통장에는 입금되었지만 매출이 아닌 돈 | 대표자가 회사에 빌려준 자금(가수금) 입금 |
| 비비용출금 | 통장에서는 출금되었지만 비용이 아닌 돈 | 대표자 가지급금 인출 |
| 미분류 | 아직 판단하지 않음(기본값) | 분류가 불확실한 모든 거래 |

- 새 거래를 등록할 때 회계구분의 기본값은 항상 **'미분류'**이며, 프로그램이 임의로
  매출/비용을 추측해서 자동으로 채우지 않습니다.
- 대시보드의 총매출/총비용은 이 회계구분을 기준으로 집계되며, 총수입/총지출(통장
  입출금 기준)과는 **다른 숫자**입니다. 예를 들어 대표자가 법인 통장에 자금을 입금하면
  통장 기준으로는 "수입"이지만, 회계구분을 '비매출입금'으로 지정하면 매출로 집계되지
  않습니다.
- 판단이 어려운 거래는 억지로 분류하지 말고 '미분류'로 남겨둔 뒤, 필요하면 세무사와
  상의해 나중에 바로잡으세요.

## 11. 기준정보 관리 - 공통 원칙 (비활성화)

**이 프로그램은 거래처·카테고리·업무유형·계정과목·자동분류 규칙을 실제로 삭제하지
않습니다.** 과거 거래와 연결되어 있을 수 있기 때문에, "삭제" 대신 **비활성화**만
제공합니다.

- 비활성화된 항목은 **신규 등록 시 새로 선택할 수 없습니다** (드롭다운에서 빠집니다).
- 이미 그 항목이 설정된 **과거 거래에는 아무 영향이 없습니다** - 조회/수정 화면에서
  기존 값 그대로 계속 보입니다.
- **대시보드 집계도 영향받지 않습니다.** 비활성화는 "앞으로 새로 선택하지 않음"을
  뜻할 뿐 "과거 통계에서 제외"를 뜻하지 않습니다.
- 비활성화된 항목은 언제든 **재활성화**할 수 있습니다.

## 12. 기준정보 관리 - 거래처

- 거래처명(필수), 기본 카테고리(선택), 기본 업무유형(선택), 메모(선택)를 등록합니다.
- 이미 등록된 이름(대소문자·공백 차이 포함)은 중복 등록을 막습니다.
- 기본 카테고리/업무유형은 거래등록 시 자동으로 채워지는 **추천값**일 뿐이며, 나중에
  바꿔도 이미 저장된 과거 거래에는 영향이 없습니다.

## 13. 기준정보 관리 - 카테고리

- 카테고리명(필수), 수입/지출 구분(필수), 정렬순서(선택)를 입력합니다.
- **수입/지출 구분은 생성 후 변경할 수 없습니다** (수정 화면에서는 읽기 전용). 잘못된
  구분으로 만들었다면 비활성화하고 올바른 구분으로 새로 추가하세요.
- 수입 또는 지출 카테고리는 **활성 상태로 최소 1개**는 항상 남아있어야 합니다.

## 14. 기준정보 관리 - 업무유형

- 업무유형명(필수), 정렬순서(선택)를 입력합니다. 동일한 이름은 중복 등록할 수 없습니다.
- 이름을 수정하면 이미 그 업무유형이 설정된 과거 거래에도 **바뀐 새 이름**이 그대로
  표시됩니다 (이름표를 갈아 끼우는 것과 같은 정상 동작입니다).

## 15. 기준정보 관리 - 계정과목

- **계정과목**은 세무사 전달용 자료에서 회계 계정(매출, 급여, 지급수수료, 여비교통비 등)을
  표시하기 위한 분류이며, **업무유형과는 완전히 별개의 분류축**입니다. 한 거래에 업무유형과
  계정과목을 동시에 지정할 수 있습니다 (예: 업무유형 "기업자문" + 계정과목 "매출").
- 프로그램 최초 실행 시 매출, 급여, 지급수수료, 여비교통비, 차량유지비, 접대비,
  복리후생비, 광고선전비, 통신비, 임차료, 소모품비, 도서인쇄비, 교육훈련비, 세금과공과,
  보험료, 외주용역비, 미수금, 미지급금, 선급금, 예수금, 가수금, 가지급금, 기타 - 23개
  기본 계정과목이 자동으로 등록됩니다.
- 계정과목명(필수), 정렬순서(선택)를 자유롭게 추가/수정할 수 있고, 삭제 대신 비활성화만
  가능합니다(11장 공통 원칙과 동일).

## 16. 기준정보 관리 - 자동분류 규칙

- 거래내용(또는 거래처명)에 특정 **키워드**가 포함되면 카테고리/거래처/업무유형/계정과목/
  회계구분을 자동으로 **추천**해주는 규칙입니다.
- **추천일 뿐 절대 자동으로 확정되지 않습니다.** 통장 가져오기(OCR) 검토 화면에서
  해당 값이 미리 선택되어 있을 뿐이며, 사용자가 언제든 다른 값으로 바꿀 수 있고, 바꾼
  값이 그대로 저장됩니다.
- 여러 규칙이 동시에 매칭되면 **더 구체적인(긴) 키워드**를 가진 규칙이 우선 적용됩니다.
- 규칙별 **사용 횟수**가 표시되어, 어떤 규칙이 실제로 자주 쓰였는지 참고할 수 있습니다.
- 삭제 대신 비활성화만 가능하며(11장 공통 원칙과 동일), 비활성화된 규칙은 더 이상
  추천에 사용되지 않습니다.

## 17. 통장 가져오기 - 파일 업로드

1. **통장 가져오기** 메뉴에서 통장 거래내역 이미지(PNG/JPG/JPEG) 또는 PDF 파일을
   선택합니다. 여러 파일을 한 번에 선택할 수 있습니다.
2. **OCR 실행** 버튼을 누르면 파일에서 날짜·시간·거래내용·입금액·출금액·잔액을
   자동으로 읽어냅니다.
3. **업로드한 원본 파일(이미지/PDF)은 OCR 처리가 끝나는 즉시 삭제되며, 프로그램
   안에 보관되지 않습니다.** 개인정보/금융정보 보호를 위한 정책입니다. 인식된 거래
   후보(텍스트 정보)만 검토 화면에 남습니다.
4. PDF 파일은 인터넷뱅킹에서 바로 내보낸 텍스트 기반 PDF라면 OCR 없이 텍스트를 바로
   읽어 정확도가 매우 높고, 스캔된 이미지형 PDF는 이미지와 동일하게 OCR로 처리됩니다.

## 18. 통장 가져오기 - 검토 화면 사용법

- **인식된 거래 후보는 절대 자동으로 저장되지 않습니다.** 반드시 이 화면에서 검토한
  뒤 직접 저장 버튼을 눌러야 실제 거래로 등록됩니다.
- 각 후보 항목을 펼치면 날짜·시간·거래내용·입금액·출금액·잔액을 **직접 수정**할 수
  있고, 카테고리·거래처·업무유형·회계구분·계정과목·부가세 여부·증빙 여부·메모도
  선택/입력할 수 있습니다 (활성 상태인 항목만 선택지에 나타납니다).
- 자동분류 규칙과 매칭되는 항목이 있으면 해당 값들이 미리 선택되어 있습니다 (추천값 -
  자유롭게 변경 가능).
- **입금액과 출금액을 동시에 입력하거나, 둘 다 비워두면 저장할 수 없습니다.** 반드시
  둘 중 하나만 입력해야 합니다.
- 저장 방법은 두 가지입니다.
  - **이 거래 저장**: 항목을 하나씩 개별적으로 저장합니다.
  - **선택한 거래 저장**: 체크박스로 여러 항목을 선택한 뒤 한 번에 저장합니다.
  - **정상 거래 전체 저장**: OCR 인식 결과가 '정상'으로 표시된 항목만 화면에 보이는
    값 그대로 한 번에 저장합니다 ('확인필요'/'중복의심' 항목은 포함되지 않습니다).
- 저장하지 않고 제외하려면 **이 항목 제외** 버튼을 누르면 됩니다 (되돌릴 수 없습니다).
- 문서 전체를 취소하려면 **이 문서 전체 취소** 버튼을 누르면 아직 저장하지 않은 모든
  후보가 한 번에 삭제됩니다.
- 한 문서의 모든 후보를 저장하거나 제외하면, 그 문서는 검토 대상 목록에서 자동으로
  사라집니다.

## 19. '확인필요' 상태의 의미

OCR이 값을 **확신할 수 없을 때** 표시되는 상태입니다. 다음과 같은 경우에 나타납니다.

- 날짜를 읽어내지 못한 경우
- 입금액과 출금액을 둘 다 읽지 못했거나, 반대로 둘 다 읽힌 경우
- 글자 인식 신뢰도가 낮은 경우

**이 프로그램은 불확실한 값을 절대로 추측해서 채우지 않습니다.** '확인필요' 항목은
사용자가 원본 통장 내역을 다시 보고 값을 직접 채우거나 고친 뒤 저장해야 합니다.
값을 고치지 않고 '정상 거래 전체 저장'을 눌러도 이 항목은 저장되지 않습니다.

## 20. '중복의심' 상태의 의미

같은 파일을 실수로 두 번 업로드하거나, 이미 수동으로 등록한 거래를 다시 OCR로
인식했을 때 표시되는 상태입니다.

- **강한 중복**: 날짜+시간+거래내용+입금/출금 구분+금액+잔액이 기존 거래와 모두 일치
- **부분 중복**: 날짜+금액+잔액만 기존 거래와 일치 (시간이나 거래내용은 다르거나
  인식되지 않음)

**두 경우 모두 절대 자동으로 삭제되거나 제외되지 않습니다.** 이미 등록된 거래인지
사용자가 직접 확인한 뒤, 중복이 맞다면 **이 항목 제외**를, 실제로는 다른 거래라면
값을 확인한 뒤 저장하면 됩니다.

## 21. CSV / Excel 내보내기

거래내역 화면에서 **현재 적용된 검색/필터 결과만** 대상으로 3가지 형식을 내려받을 수 있습니다.

| 버튼 | 형식 | 용도 |
|---|---|---|
| CSV 다운로드 | .csv | 다른 프로그램에서 활용하기 좋은 일반 형식 |
| Excel 다운로드 | .xlsx | 색상/서식이 적용된 일반 형식 |
| 세무사 전달용 Excel | .xlsx | 거래일자, 거래내용, 입금, 출금, 거래처, 회계구분, 계정과목, 업무유형, 부가세 여부, 증빙, 메모 컬럼으로 구성된 세무사 전달용 서식 |

금액은 모두 실제 숫자 셀(1,000단위 구분 서식 적용)로 저장되어 Excel에서 바로 합계를
계산할 수 있습니다.

## 22. 백업 만들기

- **설정** 메뉴에서 **💾 백업하기** 버튼을 누르면 현재 데이터 전체를 통째로 복사해
  백업 폴더(`data/backups/`)에 저장합니다.
- SQLite의 온라인 백업 기능을 사용하므로, 프로그램을 사용하는 중에도 안전하게
  백업할 수 있습니다.
- 백업 목록에서 파일명·생성 시각·크기를 확인할 수 있습니다.
- 중요한 작업(대량 데이터 정리, 백업 복구 등) 전에는 습관적으로 백업을 만들어두는
  것을 권장합니다.

## 23. 백업으로 복구하기

1. **설정** 화면의 백업 목록에서 복구할 백업을 선택합니다.
2. **♻️ 선택한 백업으로 복구** 버튼을 누르면 확인 창이 뜹니다.
3. **복구 직전의 현재 데이터는 자동으로 다시 한번 안전하게 백업된 뒤** 선택한
   백업으로 교체됩니다 (교체 도중 오류가 나도 기존 데이터가 손상되지 않도록 원자적으로
   처리됩니다).
4. 복구가 끝나면 어떤 백업으로 복구했는지, 복구 전 데이터가 어떤 이름으로
   안전하게 보관되었는지 안내 메시지가 표시됩니다.
5. **복구는 현재 데이터를 선택한 시점의 데이터로 완전히 되돌리는 작업입니다.** 복구
   이후에 입력한 내용은 모두 사라지니 신중하게 실행하세요 (다만 위 3번 덕분에, 복구
   직전 데이터도 별도 백업으로 남아있어 필요하면 다시 되돌릴 수 있습니다).

| 거래 데이터 (실제 DB 파일) | `data/finance.db` |
| 백업 파일 | `data/backups/` |
| OCR 업로드 임시 파일 | `data/temp/` (OCR 처리 직후 즉시 삭제되어 평소에는 비어 있음) |

이 파일/폴더들은 모두 `.gitignore`에 등록되어 있어 Git 저장소에 올라가지 않습니다.

## 25. 개인정보 및 보안 안내

- 이 프로그램은 **로컬 전용**으로 설계되었습니다. `streamlit run app.py`로 실행하면
  기본적으로 내 컴퓨터(localhost)에서만 접속할 수 있으며, 외부 인터넷에 공개하도록
  설계되지 않았습니다. 같은 컴퓨터를 쓰는 다른 사람과 공유하려는 목적이 아니라면
  네트워크 설정을 임의로 바꾸지 마세요.
- 업로드한 통장 이미지/PDF 원본은 OCR 처리 즉시 삭제되어 장기 보관되지 않습니다
  (17장 참고).
- API 키 등 민감한 값은 코드에 직접 저장하지 않으며, 현재 기본 OCR 엔진(Tesseract)은
  외부 서버로 이미지를 전송하지 않는 완전 로컬 처리 방식입니다.
- 거래 데이터(`data/finance.db`), 백업 파일, 업로드 임시 파일은 모두 Git에 올라가지
  않도록 처리되어 있습니다. 이 프로젝트를 Git 저장소로 관리한다면, `git status`로
  가끔 확인해 민감한 파일이 실수로 추가되지 않았는지 점검하는 것을 권장합니다.

## 26. OCR 인식의 한계

- OCR은 통장 이미지의 화질, 글꼴, 표 형식에 따라 인식률이 달라집니다. **손글씨, 저해상도
  이미지, 특이한 서식의 통장은 인식률이 낮을 수 있습니다.**
- OCR은 **입금/출금 방향만** 판단하며, 그 거래가 매출인지 비용인지(회계구분)나 어떤
  계정과목인지는 **절대 스스로 판단하지 않습니다.** 자동분류 규칙이 있으면 추천만 할
  뿐, 최종 확정은 항상 사용자가 검토 화면에서 합니다.
- 값이 불확실하면 추측해서 채우지 않고 반드시 '확인필요'로 표시합니다 - 이는 결함이
  아니라 잘못된 데이터가 조용히 저장되는 것을 막기 위한 의도된 동작입니다.
- **OCR로 인식한 결과라도 저장 전에는 반드시 원본 통장 내역과 눈으로 대조 확인하세요.**
  이 프로그램은 어떤 경우에도 검토 없이 자동으로 거래를 확정하지 않지만, 사용자가
  검토 없이 그대로 저장하면 잘못된 데이터가 들어갈 수 있습니다.

## 27. 다른 PC로 옮기기 / 이관

- `data` 폴더 전체(`finance.db`와 `backups` 폴더 포함)를 통째로 복사해 새 PC의 같은
  위치에 붙여넣으면 그대로 이어서 사용할 수 있습니다.
- 또는 [22장](#22-백업-만들기)에서 만든 백업 파일 하나만 옮긴 뒤, 새 PC에서 프로그램을
  한 번 실행해 빈 DB를 만들고 [23장](#23-백업으로-복구하기)의 방법으로 그 백업을
  복구해도 됩니다.

## 29. 자주 묻는 질문 (FAQ)

**Q. 여러 개의 통장을 관리할 수 있나요?**
A. 아니요. 이 프로그램은 법인 사업용 통장 1개를 관리하는 용도로 설계되었습니다.

**Q. 세무사에게 자료를 넘길 때는 어떤 파일을 주면 되나요?**
A. 거래내역 화면에서 **세무사 전달용 Excel**을 다운로드해서 전달하면 됩니다 ([21장](#21-csv--excel-내보내기)).

**Q. 회계구분을 잘못 지정했어요. 고칠 수 있나요?**
A. 네, 거래내역 화면에서 해당 거래를 선택해 언제든 수정할 수 있습니다 ([8장](#8-거래-수정--삭제)).

**Q. OCR로 인식된 거래를 실수로 저장했어요.**
A. 거래내역 화면에서 해당 거래를 찾아 수정하거나 삭제하면 됩니다. 저장 전 단계라면
검토 화면의 "이 항목 제외"로 되돌릴 수 있습니다.

**Q. 카테고리/거래처/업무유형/계정과목을 실수로 만들었어요. 지울 수 있나요?**
A. 완전 삭제는 지원하지 않고, 대신 **비활성화**할 수 있습니다 ([11장](#11-기준정보-관리---공통-원칙-비활성화)).
이미 그 항목을 쓰는 거래가 있을 수 있어, 삭제 대신 안전한 비활성화 방식을 사용합니다.

**Q. 이 프로그램만으로 법인세/부가가치세 신고를 할 수 있나요?**
A. 아니요. 이 프로그램은 통장 거래내역을 정리하고 세무사에게 전달할 자료를 준비하는
도구일 뿐이며, 세무 신고 자체는 지원하지 않습니다. 반드시 세무사 등 전문가와 함께
최종 신고를 진행하세요.

### 테스트 실행 방법

실제 데이터를 건드리지 않는 임시 DB를 사용해 자동 검증 스크립트를 실행할 수 있습니다.

```
python tests/test_stage1.py
python tests/test_stage2.py
python tests/test_stage3.py
python tests/test_stage4.py
python tests/test_stage5.py
python tests/test_stage5_performance.py
python tests/test_stage6.py
```

모든 스크립트는 `tests/` 폴더 아래에 임시 DB 파일을 만들어 사용하고, 종료 시 자동으로
삭제하므로 `data/finance.db`는 절대 읽기/쓰기/삭제하지 않습니다.

화면을 직접 눈으로 확인하고 싶다면, 실제 데이터 대신 별도의 DB 파일을 가리키게 해서
안전하게 띄워볼 수 있습니다 (Windows cmd 기준):

```
set FINANCE_DB_PATH=C:\temp\test_finance.db
streamlit run app.py
```

`FINANCE_DB_PATH`를 지정하지 않으면 평소처럼 `data/finance.db`를 사용합니다.
